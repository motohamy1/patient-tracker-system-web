  <files>supabase/migrations/0002_rls.sql</files>
  <read_first>.planning/phases/03-authentication-organizations-rbac-and-rls/03-RESEARCH.md (Pattern 4 lines 279-312, Pitfalls 5-7, 9, anti-pattern 'One for all policy'), 03-CONTEXT.md D-09/D-11</read_first>
  <action>
Second migration, authoring from Pattern 4 verbatim structure with the docs-mandated rules:

1. `create schema if not exists private;` then `private.user_org_role(p_org_id uuid) returns text` — language plpgsql, security definer, `set search_path = ''`, stable; body selects role from public.memberships where user_id = (select auth.uid()) and org_id = p_org_id. Then revoke execute on it from public and anon, grant usage on schema private to authenticated only.
2. For organizations, memberships, invitations: `enable row level security` + revoke ALL from anon, authenticated, service_role + explicit grant per needed op (Pitfall 6 — policies never revoke grants). Grant select to authenticated on all three; no insert/update/delete grants on memberships (writes flow ONLY through plan-task server actions that operate under RLS-allowed paths and the definer redeem function) except: authenticated insert on organizations where created_by = auth.uid() (D-01 owner bootstrap), authenticated insert on invitations gated by policy.
3. Policies — each with explicit `TO authenticated` (anti-pattern: one policy or bare both-roles), and each auth.uid() guard written as `(select auth.uid()) IS NOT NULL AND ...` form (Pitfall 5), all helper calls wrapped as `(select private.user_org_role(org_id))` (Pattern 4 initPlan rule):
   - memberships select: user_id = auth.uid() OR owner capability: helper = 'admin_owner' (member list surface reads org memberships; D-15's audit read is separate).
   - memberships update/delete: NO policy (no grant) — member removal goes through plan 03-05's server action calling a definer function so RLS recourses remain explicit.
   - organizations select: helper(org_id) IS NOT NULL (member sees own org). No update policy + no update grant (name changes deferred).
   - organizations insert: with check created_by = auth.uid().
   - invitations select: helper = 'admin_owner' OR 'provider_doctor' in own org (invite creation surface). invitations insert: with check helper in ('admin_owner','provider_doctor') — D-01: owner creates invites.
4. No policy on any table may read the other side's table directly through a non-definer path (Pitfall 7 recursion rule) — the definer helper is the ONLY membership reader inside policies.
5. UPDATE policies where any exist carry both using and with check (Pitfall 9). If a table gets no update policy, record the reasoning in the file header (capability not expressible at Phase 3).
6. Capability note in header: role→operation mapping mirrors D-09 constants table (plan 03-03); the check-constraint strings are the shared vocabulary. Header cites AUTH-02/AUTH-04/AUTH-05, D-09/D-10/D-11.
