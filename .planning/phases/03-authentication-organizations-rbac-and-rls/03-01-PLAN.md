Read env values through a small check so a missing env produces a named error, NOT undefined silently.

2. `src/lib/supabase/client.ts` — export a browser client getter (Pattern: one module-level singleton of `createBrowserClient`, created lazily so it is never evaluated during SSR).

3. `src/lib/supabase/proxy.ts` — export `updateSession(request: NextRequest)` returning a `NextResponse`, per the official SSR proxy pattern: create a request-scoped server client with request cookie getAll/setAll, call `supabase.auth.getClaims()` (the JWT-verifying call — NEVER `getSession()` for identity), then return NextResponse.next with the request.cookies.setAll + response.cookies.setAll applied so refreshed cookies reach both the RSC context and the browser, preserving cache-control/expires/pragma headers.

4. `src/proxy.ts` — Next 16 convention (Pitfall 1: middleware.ts is NEVER called on 16.3.8): default or named `proxy` export delegating to updateSession; `config.matcher` excluding _next/static, _next/image, favicon, static asset extensions — copy the matcher regex from Pattern 2.

5. The proxy file performs ONLY session refresh — no route gating, no role reads, no redirects (D-06 + AUTH-03; role protection is Phase-3 RSC resolution + RLS which plans 03-02/03-03 deliver). Add no redirect() anywhere in src/lib/supabase/.

6. Header comment discipline (established codebase convention per 03-PATTERNS Shared Pattern 1): each new file opens with a comment block citing the decisions it implements (D-05/D-06, AUTH-01/AUTH-03) and the governance/RESEARCH source. This is the one sanctioned comment usage.
