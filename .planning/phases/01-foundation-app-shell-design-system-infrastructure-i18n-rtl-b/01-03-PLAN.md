  <action>
Move the app under `src/app/[locale]/` so every route is locale-prefixed and RTL is correct from the first component (locked decision D1).

Create `src/app/[locale]/layout.tsx` as a **Server Component** — it must NOT have `"use client"`:

    import type { Metadata } from 'next';
    import { notFound } from 'next/navigation';
    import { isLocale, directionOf, locales, type Locale } from '@/i18n/routing';

    export function generateStaticParams() {
      return locales.map((locale) => ({ locale }));
    }

    export const metadata: Metadata = { title: 'Clinical Patient Workspace' };

    export default async function LocaleLayout({
      children,
      params,
    }: {
      children: React.ReactNode;
      params: Promise<{ locale: string }>;
    }) {
      const { locale } = await params;
      if (!isLocale(locale)) notFound();
      const dir = directionOf(locale as Locale);
      return (
        <html lang={locale} dir={dir}>
          <body>{children}</body>
        </html>
      );
    }

Notes that matter:
- `params` is a Promise in Next 16 — `await params` before reading. Verify the exact signature against the installed Next 16 types; if the compiler disagrees, follow the installed types and note it in the SUMMARY.
- `dir` is resolved ON THE SERVER and passed down as a plain string. Do NOT compute direction in a client hook — that makes first paint wrong.
- Add a comment recording that `next-intl` was deliberately NOT added, with the Phase 4 / Phase 2 rationale.

Replace the Phase 1 placeholder `src/app/layout.tsx` and `src/app/page.tsx`: delete `src/app/layout.tsx` (the `[locale]` layout is now the only root layout — having both causes a Next error) and replace `src/app/page.tsx` with a redirect to the default locale:

    import { redirect } from 'next/navigation';
    import { defaultLocale } from '@/i18n/routing';

    export default function RootPage() {
      redirect(`/${defaultLocale}`);
    }

Create `src/app/[locale]/page.tsx` as a minimal shell that exercises the primitives so the visual harness has something real to capture: `AppFrame` wrapping `NotchHeader` (title = locale-aware label) with a `PrimaryPillTabs`, one `ModuleSurface`, one `Chip`, one `AccentNode`, and one `DarkScrubber`. This is a composition demo for the design gallery's sibling route, NOT a clinical screen — no patient data, no auth, no tabs beyond the shell.

Locale-aware labels: pass `'Overview'` / `'نظرة عامة'` style pairs through the locale rather than hardcoding English. Do not introduce a message-catalog library; a small inline map keyed by locale is correct for Phase 1.

Do NOT create `proxy.ts` or `middleware.ts` in this plan. Next 16 renamed the convention to `proxy.ts` and a `middleware.ts` file is silently never called; locale negotiation and Supabase session refresh both need that single proxy, which is a Phase 2 decision.
