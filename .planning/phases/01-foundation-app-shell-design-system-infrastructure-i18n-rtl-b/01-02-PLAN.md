Why `static` and not the default: the default emits a CSS custom property only for tokens actually used, so `getComputedStyle(el).getPropertyValue('--shadow-module')` returns an empty string for an unused token. Later phases read these tokens programmatically; `static` guarantees every token is emitted.

Why `--color-*: initial`: the pack forbids multicolor palettes and pastel surfaces. Removing Tailwind's default palette makes that structurally enforced rather than a review comment.

Font wiring: if `next/font` families are added later, change to `@theme inline` for the font tokens (a token that references another variable needs `inline` or the utility resolves to an unexpected fallback).

Create `src/styles/tokens.dark.css` as a reserved, currently EMPTY override file with a header comment stating that dark-mode value overrides go in `:root` inside a media query here, never inside `@theme` (a nested `@theme` silently does nothing). Do not implement dark mode — Phase 1 ships light only.

Wire both into `src/app/globals.css`:

    @import "tailwindcss";
    @import "../styles/tokens.css";
    @import "../styles/tokens.dark.css";

    @layer base {
      /* Reset the outer field to the single accent so the olive frame reads against it. */
      body {
        background-color: var(--color-accent);
        color: var(--color-ink-strong);
      }
      /* Clinical numerals stay Western in every locale (locked decision D1). */
      :root {
        --clinical-numbering: latn;
      }
    }

Do NOT put physical direction properties anywhere: no `margin-left`, `margin-right`, `left:`, `right:`, `text-align: left`, `text-align: right`, `rounded-tl-`, `rounded-br-`. Logical forms only (`padding-inline`, `margin-block`, `inset-inline`, `border-start-start-radius`, and Tailwind's `ms-/me-/ps-/pe-/start-/end-/text-start/rounded-s`).

Create `src/i18n/routing.ts`:

    export const locales = ['en', 'ar'] as const;
    export type Locale = (typeof locales)[number];
    export const defaultLocale: Locale = 'en';

    export function isLocale(value: string): value is Locale {
      return (locales as readonly string[]).includes(value);
    }

    /** Direction is server-resolved and passed down as a plain string — never computed in a client hook. */
    export function directionOf(locale: Locale): 'ltr' | 'rtl' {
      return locale === 'ar' ? 'rtl' : 'ltr';
    }

Do NOT add `next-intl` or any i18n library in this phase. Written justification: Phase 1 needs only a locale list, a default, and a direction map; message catalogs arrive with real strings in Phase 4, and locale negotiation in `proxy.ts` is a Phase 2 decision point (one proxy, two concerns). PROJECT.md forbids adding dependencies without a written reason, and this records the reason for NOT adding one.

Create `src/lib/format.ts` for clinical values:

    import { defaultLocale, type Locale } from '@/i18n/routing';

    /** Clinical values always use Western digits, even under an Arabic locale (locked decision D1). */
    export function formatClinicalNumber(value: number, locale: Locale = defaultLocale, options?: Intl.NumberFormatOptions): string {
      return new Intl.NumberFormat(locale, { numberingSystem: 'latn', ...options }).format(value);
    }

    /** Egypt-appropriate units are explicit; never abbreviated silently. */
    export const clinicalUnits = {
      weight: 'kg',
      temperature: '°C',
      bloodPressure: 'mmHg',
      glucose: 'mg/dL',
    } as const;

    export function formatBloodPressure(systolic: number, diastolic: number, locale: Locale = defaultLocale): string {
      return `${formatClinicalNumber(systolic, locale)}/${formatClinicalNumber(diastolic, locale)} ${clinicalUnits.bloodPressure}`;
    }
