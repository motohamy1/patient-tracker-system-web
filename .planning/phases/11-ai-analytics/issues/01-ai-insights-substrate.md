# 11-01: AI insights substrate with provenance and human-review state

**What to build:** Stored AI insights that can never be mistaken for clinical truth. A clinician opens the AI Analytics tab and sees insights that carry their own provenance (system-derived vs AI-generated), an explicit unreviewed state, and a recorded reviewer identity once a human accepts or dismisses them.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [ ] `ai_insights` table: `kind` in a closed vocabulary (`change`, `summary`, `attention`, `trend`, `documentation-gap`), `title`, `body`, `evidence` (structured references to the real source rows the insight was derived from — table + id + label, never prose-only claims), `window` (the period the insight covers, nullable for point-in-time findings), `provenance` (`system-derived` | `ai-generated`), `verification` defaulting to `ai-extracted` (§23: AI output can never render as clinician-verified), `review_state` (`pending` | `dismissed` | `accepted`), `reviewed_by`/`reviewed_at`, org/patient FKs, timestamps — §13/§23
- [ ] No autonomous-anything affordance: the table has no column that could hold a diagnosis or a prescription decision; writes are observations only (AI-03)
- [ ] RLS: SELECT for all four staff roles in the org (assistive surface, org-scoped); INSERT for `provider_doctor` only (the in-session generator); UPDATE for `provider_doctor` + `nurse` (review transitions only — enforced by trigger, review columns immutable for every other column); no DELETE (audit trail)
- [ ] Review-transition guard trigger: only `review_state`/`reviewed_by`/`reviewed_at`/`verification` may change on UPDATE; content columns are immutable after insert
- [ ] Audit trigger on insert + update (0003 pattern) so every generated insight and every review decision is retrievable
- [ ] `database.types.ts` gains the table (hand-maintained until CLI regeneration)

**Gate evidence at close:** AI-02 (provenance + human review) · §23 · §12 · AI-03 (no autonomous decision storage)

## Notes

- Provenance vocabulary is §10's: patient-entered/staff-entered/doctor-entered/imported/AI-extracted/AI-generated/verified-by-clinician/system-derived. This table is generated by the system, so `system-derived` today; `ai-generated` is reserved for the model-backed generator a later iteration may add — the column exists so the distinction is already enforceable.
- `review_state` and `verification` are deliberately separate: an accepted insight is a clinician's *decision about an observation*, not a promotion of AI prose into the clinical record.
