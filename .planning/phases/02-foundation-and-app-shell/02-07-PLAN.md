# Plan 02-07 — `EmptyState`, and the hand-rolled `Overlay` with its full accessibility contract

## Objective

Build the last two primitives the shell needs: the single shared empty state every route renders, and the one overlay primitive — modal on desktop, bottom sheet below the 1024px edge — with the complete focus, escape, restore, `inert`, scroll-lock and labelling contract hand-rolled.

Purpose: FOUND-04 is this phase's deliverable, not a later phase's debt, and D-22 deliberately keeps that ownership here by forbidding a headless library. FOUND-02 needs a modal/sheet primitive so a later phase never invents a third overlay form. UX-06 needs the modal-to-sheet flip at the band edge to be the *same component*, not two.

Output: `EmptyState`, `Overlay`, `useFocusTrap`, `useScrollLock`, and three test files.

## Signatures

- `EmptyState({ icon, title, body, action })` where `action` is `{ label, onClick?, href? } | undefined`.
- `Overlay({ open, onClose, title, description?, children, footer? })`.
- `useFocusTrap({ active, containerRef, initialFocusRef, onDismiss })`.
- `useScrollLock({ active })`.

    Create `src/components/overlays/useFocusTrap.ts` exporting `useFocusTrap({ active, containerRef, initialFocusRef, onDismiss })`, implementing the ordered algorithm:

    1. On activation, capture `document.activeElement` **before** anything moves focus. That element is the restore target.
    2. Mark the background inert. If the overlay is portalled to `document.body`, its siblings are the application root and the injected script/style tags; setting `inert` on the application root removes the whole page behind the dialog from the tab order and the accessibility tree in one attribute. That is the single biggest correctness win over a manual "collect every tabbable" loop, which always misses something.
    3. Move focus to the first focusable inside the container, or to the container itself with `tabIndex={-1}` when the container holds none.
    4. While active, attach a single `keydown` listener on the container that handles `Tab` and `Shift+Tab`: query focusable descendants with a selector for links, non-disabled buttons, non-disabled inputs, selects and textareas, and elements carrying a non-negative `tabindex`; filter to elements with a non-zero `getClientRects().length` so hidden children are skipped; wrap `focus()` to the first and last of that list.
    5. Handle `Escape` by invoking `onDismiss`.
    6. On cleanup, remove the listener, un-`inert` the background, and restore focus to the captured element **only if it is still connected to the document**. Add a header comment recording that the connectedness guard exists because a trigger can unmount while a dialog is open — which is a real failure mode in a route-changing app — and that without it focus silently falls to the document body and a keyboard user loses their place.

## Trust Boundaries

| Boundary | Description |
|---|---|
| User keyboard input → overlay state machine | Tab, Shift+Tab and Escape are untrusted sequences arriving while focus is trapped; a mishandled wrap can strand a keyboard user outside the dialog, and a missing restore loses their place entirely. |
| Page content → `inert` boundary | Everything behind the dialog must be removed from the tab order and the accessibility tree; a missed sibling means background content stays reachable. |
| Document scroll → locked body | Locking scroll without a stable gutter shifts layout by the scrollbar width, which would move content and corrupt a visual baseline. |
| Overlay DOM → assistive technology | `role`, `aria-modal` and the labelling wiring are what a screen reader consumes; they are the only channel that tells AT the dialog is modal. |

## ASVS scope statement (recorded, not omitted)

**ASVS V2 Authentication, V3 Session Management, V4 Access Control, V5 Input Validation and V6 Cryptography were assessed and are NOT YET APPLICABLE to this plan.** The overlay renders no route and resolves no identity. **V4 in particular is assessed with a hard negative rule:** this phase creates no client-side gate of any kind and reads no role from anywhere client-held — an open route in Phase 002 is temporary by decision D-03, and a fake gate that looks real is worse than none. The access-control obligations belong to Phase 003.

**ASVS V5 Input Validation** is assessed and found inapplicable: the overlay accepts only a title, optional description and children supplied by its own caller; it accepts no user-supplied data and performs no interpolation of untrusted content into markup. The one discipline recorded by `02-RESEARCH.md` §Security Domain — that a route parameter must never be passed to anything that interprets it — applies to plan 02-08's shells, not here.

**ASVS V8 Data Protection** applies in the negative form that no clinical content may be hardcoded into an `EmptyState`; the primitive's text comes from the caller, and the caller's copy is plan 02-08's contract. **ASVS V12 Files and Resources** does not apply — no upload, no user path. **ASVS V14 Configuration** does not apply — no environment variable is read here.
