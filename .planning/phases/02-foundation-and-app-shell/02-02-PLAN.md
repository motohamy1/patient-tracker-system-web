# Plan 02-02 — Repository scaffold, pinned dependency install, and the build hooks

## Objective

Create the entire build scaffold the rest of the phase runs on: a `package.json` with the exact script set, a committed lockfile, TypeScript with `strict`, the Next.js config, the PostCSS bridge to Tailwind v4, and a `.gitignore` that makes the generated token artifacts uncommittable.

Purpose: D-05 and D-13 are enforced through npm lifecycle hooks, so the hook definitions and the dependency set are not incidental setup — they are the mechanism the token contract depends on. Getting the hooks wrong means a build can ship with zero token utilities and every `bg-surface` silently rendering unstyled (`02-RESEARCH.md` Pitfall 5).

Output: an installable, buildable repository with the pinned stack and the exact script names later plans wire into.

## Install commands (exact, from `02-RESEARCH.md` §Standard Stack)

Note `gsap` pins to `3.15.0` — not `15.0.0`.

```
npm install next@16.3.8 react@19.3.0 react-dom@19.3.0 tailwindcss@4.3.3 @tailwindcss/postcss@4.3.3 motion@14.0.0 gsap@3.15.0 lucide-react@1.52.0
npm install -D typescript@~5.9 @types/node @types/react@19 @types/react-dom@19 @playwright/test@1.63.0 vitest@5.0.3 @vitejs/plugin-react@6.1.2 jsdom@30.1.2
npx playwright install chromium
```

## Why the dependency set is exactly this set

Thirteen packages, no more. Every one was audited against the npm registry in Phase 001 (`02-RESEARCH.md` §Package Legitimacy Audit): canonical GitHub repository, published by the same maintainers as the library it is, and an **empty `postinstall`** on every one of them. Tailwind v4 ships no `tailwind.config.js` — it is CSS-first, so a v3-style config would be silently ignored — which is why `postcss.config.mjs` carries a single plugin and nothing else. `lucide-react` and `motion` were audited in Phase 001 and pinned. `gsap` is installed for Phase 006's timeline choreography and is **not imported anywhere in Phase 002 code** (`docs/governance/motion-rules.md` §2 assigns SVG/timeline choreography to Phase 006).

No `@testing-library/*` package is installed. The primitive tests of plan 02-05 render with `react-dom/server` — already present as a transitive dependency of `react` — and assert against parsed DOM; the interactive overlay tests of plan 02-07 use the `jsdom` environment's own `document`. No renderer library is added anywhere in this phase.
