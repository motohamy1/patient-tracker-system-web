# Phase 2 — UI Design Contract (Foundation and App Shell)

> Visual and interaction contract for the foundation phase. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`. Downstream consumers: `gsd-planner` (token utilities, primitive inventory, copy), `gsd-executor` (visual source of truth while implementing), `gsd-ui-auditor` (retrospective comparison).

---

## 0. Scope, authority and reading order

**Authority.** `docs/governance/tokens.json` is the frozen value source. This document restates **no color value** — every color below is a **token name**, and the value lives in the JSON, reaching the browser only through the generated CSS layer (`docs/governance/tokens.json` → `@theme inline` + `:root`, D-05/D-07/D-08). Scale values (spacing steps, type sizes, icon sizes) **are** shown numerically in the tables below for readability and match `tokens.json` exactly; where a table and the JSON ever disagree, **the JSON wins**. `docs/governance/ui-invariants.md` → `INV-01`…`INV-17` and `docs/governance/visual-qa-rules.md` → rows 1…12 outrank this document wherever they disagree.

**No raw color value appears in this file** — not as a design token, not in an example, not in a contrast calculation. This mirrors the construction used in `docs/governance/reference-ui-specification.md` §2.1, where the "Resolves to" cell is a *citation*, not a value.

**What this phase builds visually.** The route map as empty shells (D-01), the three route-group layouts (D-02), the primitive set (Surface, Button, Pill/Tab, compact control, Overlay, EmptyState, Icon), the accessibility baseline (FOUND-04), the motion foundation (FOUND-05), and the dev-only primitives gallery (D-16, D-26).

**What this phase does not build.** Any clinical capability, the folder grid, the 8-tab workspace body, the D3 timeline, popovers, checkboxes, toasts, dropdown menus, tooltips, or a fourth overlay. Each is introduced by its owning phase with its own contract. A primitive that this phase does not specify **does not exist** in Phase 2 — a later phase that needs one writes its contract first.

## Spacing Scale

One six-step scale, read from `docs/governance/tokens.json` → `space`. **No spacing value outside this scale exists**, and no page-level section break exceeds the `space.2xl` step (`INV-10`).

| Token | Value | Generated utility | Usage in Phase 2 |
|-------|-------|-------------------|-------------------|
| `space.xs` | 4px | `gap-xs`, `p-xs` | Icon-to-label gap; timeline node-to-label offset |
| `space.sm` | 8px | `gap-sm`, `p-sm` | Compact control padding-y; status pill insets; rail item padding |
| `space.md` | 12px | `gap-md`, `p-md` | Compact control padding; sheet outer inset; list row spacing |
| `space.lg` | 16px | `gap-lg`, `p-lg` | Dense card inner padding; top-bar horizontal padding |
| `space.xl` | 24px | `gap-xl`, `p-xl` | Section padding; card-to-card gaps; modal outer inset |
| `space.2xl` | 32px | `gap-2xl`, `p-2xl` | Major layout gaps; page edge padding |

**Exceptions (the only two).** (1) Touch targets of at least 44px in both axes below the 768px band edge — a **target size**, not a spacing value; it never extends the scale (`INV-10`, `docs/governance/responsive-rules.md` §4). (2) Layout *widths* and *heights* that are neither a gap nor a padding (the rail width, the control heights in §5.4) — these are component dimensions, not spacing steps, and they are enumerated explicitly so the reviewer can see them rather than infer them.

**Prohibited.** A page-level section break above the `space.2xl` step; any off-scale value introduced to "make something fit"; a mobile-only spacing value. Density changes by choosing a **different step of the same scale**, never by inventing a value.

## Typography

Exactly four sizes and exactly two weights, read from `docs/governance/tokens.json` → `font` (D-20, `INV-07` for radius-equivalent strictness of the type scale).

| Role | Token | Value | Weight | Line height | Generated utilities |
|------|-------|-------|--------|-------------|---------------------|
| Display / stat value | `font.size.display` | 28px | `font.weight.semibold` (600) | `font.lineHeight.tight` | `text-display`, `font-semibold`, `leading-tight` |
| Heading / card and section title | `font.size.heading` | 16px | `font.weight.semibold` (600) | `font.lineHeight.heading` | `text-heading`, `font-semibold`, `leading-heading` |
| Body | `font.size.body` | 14px | `font.weight.regular` (400) | `font.lineHeight.body` | `text-body`, `font-regular`, `leading-body` |
| Label / secondary / axis | `font.size.label` | 12px | `font.weight.regular` (400) | `font.lineHeight.label` | `text-label`, `font-regular`, `leading-label` |

**Binding rules.**

- `tabular-nums` is set on **every** clinical, statistical and numeric value — the empty-state action row, stat readouts later, and any count or date column.
- The eyebrow style (the reference's "MEDICATION REMINDER:") is `font.size.label` at weight **400** with `text-transform: uppercase` and `letter-spacing: 0.08em`. A 500 weight is **not allowed**.
- Weights are **400 and 600 only**. A 700 weight is never added; a title the eye reads as "bold" is 600 at the declared size.
- The body minimum for non-decorative text is 12px.
- Icons never carry text. An icon paired with a label uses `gap-xs`.

## Color

The 15-token semantic contract from `docs/governance/tokens.json` → `color`. Names are canonical; values are never restated here.

| Role | Token(s) | Resolves to | Usage |
|------|----------|-------------|-------|
| Dominant — 60% | `canvas`, `frame` | `tokens.json` → `color.canvas`, `color.frame` | `canvas` is the workspace field; `frame` is structural chrome (top bar, side rail). Both light — the frame is **never** a dark surface (D-01, `INV-02`). |
| Secondary — 30% | `surface`, `surfaceMuted`, `surfaceRaised` | `tokens.json` → `color.surface`, `color.surfaceMuted`, `color.surfaceRaised` | `surface` = default card; `surfaceMuted` = inset panel (search field, inset note field, scrubber track later); `surfaceRaised` = elevated card, active tab pill, modal and sheet panel. |
| Accent — 10% | `accent`, `accentSoft` | `tokens.json` → `color.accent`, `color.accentSoft` | `accent` = timeline chartreuse, reserved list only. **`accentSoft` carries the provider-home primary CTA and key interaction buttons.** |
| Destructive / critical | `critical` | `tokens.json` → `color.critical` | Destructive actions and critical-alert accents. Soft fills render as `critical` over `surface` — never a new token. |
| Semantic status | `success`, `info`, `warning` | `tokens.json` → `color.success`, `color.info`, `color.warning` | Status encoding **only**, and only as a decorative tint (§4.3). |

**Accent reserved for — the two lists are exhaustive and mutually exclusive.**

`accent`: timeline event nodes and their count badges; timeline milestone markers; active/selected emphasis markers; key state indicator dots; important-interaction highlights.

`accentSoft`: the provider-home primary CTA; key interaction buttons.

A primary CTA painted `accent` **fails** `INV-05` and QA row 12. `accent` is never for folder cards, body text, borders, backgrounds, decorative fills, or every icon. A selected scrubber range is not accent — it is the dark overlay viewport window.

### 4.3 Status encoding — color is never the only channel

**This is a load-bearing rule, not a preference.** Every semantic status token in the frozen palette is a light tint. Measured against `canvas`, `surface` and `surfaceRaised`, **all four status tints measure between 1.0:1 and 1.4:1** — far below the 3:1 non-text threshold and the 4.5:1 text threshold. `textSecondary` measures 1.3:1 on `surface` and `frameForeground` 1.8:1 on `frame` (computed by the `docs/governance/reference-ui-specification.md` §3 method, reported in §6). They are decorative. Consequences, binding on every primitive in §5:

- **All text is painted `textPrimary`.** No label, heading, value or button label in Phase 2 uses `textSecondary`, `frameForeground` or a status tint. This is the single rule that carries FOUND-04.
- **Status is carried by text, never by hue alone.** A status element is a `radius.pill` chip whose label is `textPrimary` at `font.size.label`, preceded by a small tint dot or icon in the status token. Removing all color leaves the meaning intact — `WCAG 1.4.1 Use of Color`, and the correct reading of `INV-04` for a clinical product.
- **A tint is never the only boundary.** No control relies on a tint for its edge; `textPrimary` ink and, where an edge is needed, `shadow.raised` carry the boundary.
- **`frameForeground` is reserved for frame decoration only** — the vendor mark glyph and inactive decorative detail. It is never an icon that navigates, never a label, never a control boundary. See §6 for the reviewer item this raises against `reference-ui-specification.md` §2.1.

### 4.4 Multi-hue restriction

Folder tab headers and status chips encode meaning with `success`, `info` and `warning` only (D-04). The pastel quick-log chips visible in the patient-home primary are **decorative icon tints** rendered from `canvas`, `surface` and `borderSubtle` — no new tint family is added, and none is added in Phase 2. The multi-hue chart colors visible in the provider-home Daily Stats sparklines are **not** reproduced by any Phase 2 primitive; no gallery section may introduce them, as that would import a tint family and a generic-substitution risk in one step.

## Primitive Inventory

Every primitive below is built **only** from generated token utilities. The utility vocabulary is exhaustive and derived from `tokens.json` — FOUND-02 is satisfied by composition from this set, never by a hand-rolled per-screen component.

| Primitive | Variants / sizes | Radius | Shadow |
|-----------|------------------|--------|--------|
| `Surface` | `canvas`, `surface`, `surfaceMuted`, `surfaceRaised` | `radius.md` / `radius.lg` / `radius.xl` by size | see §5.1 |
| `Button` | `primary`, `secondary`, `ghost`, `iconOnly` | `radius.pill` (`INV-08`) | see §5.2 |
| `Pill` (status) | `success`, `info`, `warning` | `radius.pill` | none |
| `TabBar` / `SegmentedControl` | active + inactive; `overflow` variant for mobile | `radius.pill` | `shadow.raised` on active pill only |
| `CompactControl` | `search`, `iconToggle`, `rangeToggle` | `radius.pill` | `shadow.raised` on raised variants only |
| `EmptyState` | title + optional body + optional action | `radius.xl` | `shadow.raised` |
| `Overlay` | `modal` (≥1024px), `sheet` (<1024px) — one primitive, one presentation variant (D-23) | `radius.xl` | `shadow.overlay` |
| `Icon` | `size.lg` (24px), `size.md` (16px) | n/a | none |

### 5.1 `Surface` — four variants, one component (D-25, `INV-16`, `INV-13`, `INV-14`)

| Variant | Fill utility | Radius | Padding | Shadow | Role |
|---------|--------------|--------|---------|--------|------|
| `canvas` | `bg-canvas` | none (full-bleed field) | none | **none** | Page field. A field is not a card. |
| `surface` | `bg-surface` | `rounded-lg` (`radius.lg`) | `p-lg` | **`shadow-raised`** | Default card. |
| `surfaceMuted` | `bg-surface-muted` | `rounded-lg` | `p-lg` | **none** | Inset panel: search field, inset note field, scrubber track. |
| `surfaceRaised` | `bg-surface-raised` | `rounded-xl` (`radius.xl`) | `p-xl` | **`shadow-raised`** | Elevated card, active tab pill, modal and sheet panel (panel additionally takes `shadow.overlay`). |

**Binding rules.**

- **No card renders a visible full-perimeter border** (`INV-16`). Card edges separate by shadow. No `border` utility appears on any card variant.
- **`surfaceMuted` takes no shadow.** Recess is expressed by fill, not by an inset shadow — an inset would be a third elevation level and fails `INV-13`. The reference's pressed note field is reproduced with `surfaceMuted` fill and no third shadow.
- Only `shadow-raised` and `shadow-overlay` exist. A component never declares a local box-shadow value (`INV-14`).
- Card padding uses `space.lg` for dense provider/workspace cards and `space.xl` for the sparser patient-home range — the same scale, two densities (`docs/governance/responsive-rules.md` §1).

### 5.2 `Button` — four variants, `radius.pill` throughout (`INV-08`)

| Variant | Fill | Ink | Height | Padding-x | Icon | Shadow |
|---------|------|-----|--------|-----------|------|--------|
| `primary` | `bg-accent-soft` | `text-text-primary` | 44px (≥768px: 32px) | `space.xl` | leading, 16px, `gap-xs` | **none** |
| `secondary` | `bg-surface-raised` | `text-text-primary` | 44px (≥768px: 32px) | `space.xl` | leading, 16px, `gap-xs` | `shadow-raised` |
| `ghost` | transparent | `text-text-primary` | 44px (≥768px: 32px) | `space.md` | leading, 16px, `gap-xs` | **none** |
| `iconOnly` | `bg-surface-raised` | `text-text-primary` | 44px minimum in **both** axes at every band | square, `p-sm` | single 24px icon | `shadow-raised` |

**Binding rules.**

- **`primary` is filled with `accentSoft`, never `accent`** (`INV-05`, QA row 12). A primary CTA painted `accent` fails the phase.
- **No state change swaps the fill for a status or tint color.** `hover`, `active` and `focus` all move through opacity of the same fill plus, for `primary`, no shadow. A hover state that paints `accent` fails `INV-05`.
- `hover` / `active` / `focus-visible` transitions run at `duration.fast` with `easing.standard` (`docs/governance/motion-rules.md` §1). No bounce, no overshoot, no attention loop.
- **`disabled`** — `opacity` reduced on the existing fill and ink, `cursor: not-allowed`, `aria-disabled` or the `disabled` attribute as the semantics require, no shadow change, no focus ring. The provider-home CTA renders **disabled** in Phase 2 because Phase 004 owns its destination (D-01, D-18).
- Every `iconOnly` button ships an **accessible name** — `aria-label` on every one, per `docs/governance/reference-ui-specification.md` §4. An icon-only control with no accessible name never ships in the DOM.
- Below the 768px band edge every button, including `iconOnly` and a `primary` at rest, is at least 44px in both axes. At and above 768px, text buttons may be 32px tall; icon-only buttons stay 44px in both axes at every band, because they are pointer-and-thumb targets.

### 5.3 `Pill` (status), `TabBar` and `SegmentedControl`

| Element | Fill | Ink | Radius | Padding | Shadow |
|---------|------|-----|--------|---------|--------|
| Status `Pill` | `bg-surface-muted` | label `text-text-primary`; leading dot in `success` / `info` / `warning` | `rounded-pill` | `px-md`, `py-sm` | **none** |
| `TabBar` container | `bg-surface-muted` | — | `rounded-pill` | `p-xs` | **none** |
| `TabBar` active item | `bg-surface-raised` | `text-text-primary` + 16px icon | `rounded-pill` (inherits) | `px-md`, `py-sm` | `shadow-raised` |
| `TabBar` inactive item | transparent | `text-text-primary` | `rounded-pill` (inherits) | `px-md`, `py-sm` | **none** |
| `SegmentedControl` active | `bg-surface-raised` | `text-text-primary` | `rounded-pill` | `px-md`, `py-sm` | `shadow-raised` |
| `SegmentedControl` inactive | transparent | `text-text-primary` | `rounded-pill` | `px-md`, `py-sm` | **none** |

**Binding rules.**

- Inactive and active items carry **the same ink** (`textPrimary`). Active state is expressed by fill plus `shadow.raised` — never by a color swap, which would fail §4.3.
- The **patient-workspace tab set is exactly** `Overview | AI Analytics | Visits | Medications | Labs | Imaging | Allergies | Genetics`. The `Vital Signs` and `Communication` tabs visible in the reference are sample content and never become route names or tab labels (`AGENTS.md` §Navigation, Phase 001 D-13). They are rendered as the eight nested routes under `/provider/patients/[patientId]`.
- `aria-current="page"` on the active item. Tab semantics use `role="tab"` / `aria-selected` when the group drives a panel, otherwise plain links with `aria-current`.
- Below 768px the tab group becomes a **horizontally scrolling pill strip** — never a collapsed hamburger-only pattern on a surface where tabs are primary (`docs/governance/responsive-rules.md` §4). Scrolling edge: `scrollbar-width: none` with the strip remaining keyboard-scrollable and each item reachable in DOM order.

### 5.4 `CompactControl`

| Variant | Fill | Ink | Radius | Height | Padding-x | Shadow |
|---------|------|-----|--------|--------|-----------|--------|
| `search` | `bg-surface-muted` | placeholder `text-text-primary`; search icon `text-text-primary` | `rounded-pill` | 44px below 768px, 32px at/above | `space.lg` | **none** |
| `iconToggle` (off) | `bg-surface-muted` | `text-text-primary` | `rounded-pill` | 44px both axes | `p-sm` | **none** |
| `iconToggle` (on) | `bg-surface-raised` | `text-text-primary` | `rounded-pill` | 44px both axes | `p-sm` | `shadow-raised` |
| `rangeToggle` (inactive) | transparent | `text-text-primary` | `rounded-pill` | 44px below 768px, 32px at/above | `space.md` | **none** |
| `rangeToggle` (active) | `bg-surface-raised` | `text-text-primary` | `rounded-pill` | 44px below 768px, 32px at/above | `space.md` | `shadow-raised` |

**Binding rules.**

- **No compact control renders a border.** `borderSubtle` is reserved for true dividers, table row lines, the timeline axis and the scrubber track (`INV-15`, D-05). The reference's search field is a filled capsule with no edge — reproduced exactly that way.
- Every control ships a label or an `aria-label`; the search input additionally carries `type="search"` and a programmatic label.
- Icon sizes are **exactly two** — 16px (`font.size.body`-aligned, paired with a label) and 24px (standalone, icon-only controls). Icon geometry is bound to existing scale steps so an icon size can never introduce an off-scale value.

### 5.5 `EmptyState` — one shared primitive (D-24)

| Slot | Token spec |
|------|------------|
| Wrapper | `Surface` `surfaceRaised` variant, `rounded-xl`, `shadow-raised`, `p-xl`, `max-w-lg`, `mx-auto`, centred content, `text-center` |
| Title | `text-heading`, `font-semibold`, `leading-heading`, `text-text-primary` |
| Body | `text-body`, `font-regular`, `leading-body`, `text-text-primary`, `max-w-sm`, `mx-auto`; omitted entirely when there is nothing to say |
| Action | `Button` `secondary` by default; `primary` only where the empty state's next step **is** the surface's primary action, and then filled `accentSoft` (`INV-05`) |
| Icon | optional 24px `Icon` in `text-text-primary` above the title, `gap-sm` to the title. Never a status tint, never an accent. |

**Binding rules.**

- The action slot renders **only when the destination exists and is wired**. In Phase 2 no shell route has a wired destination, so no shell route renders an action; the gallery renders it so the primitive's appearance is baseline-capturable. A dead enabled button never ships.
- **Never a spinner and never a generic skeleton.** This primitive is the empty variant; the loading, error, retry, permission-denied and offline-sync variants belong to Phase 003 (`UX-01`, `AGENTS.md` §8).
- No card in the shell holds one line of content or fewer without a stated information purpose (`INV-12`); the empty state is that stated purpose.

### 5.6 `Overlay` — one primitive, two presentations (D-22, D-23)

| Element | Token spec |
|---------|------------|
| Scrim | `background-color` resolving to `textPrimary` at reduced opacity. **No new scrim token is introduced** (`INV-17`); the scrim is `textPrimary` with alpha only. No `backdrop-blur` beyond what the reference shows. |
| Panel — `modal` (≥1024px) | `Surface` `surfaceRaised`, `rounded-xl`, `shadow-overlay`, `p-xl`, centred, `max-w-lg`, outer inset `space.xl` |
| Panel — `sheet` (<1024px) | `Surface` `surfaceRaised`, `rounded-xl`, `shadow-overlay`, `p-xl`, anchored to the bottom edge, full width, outer inset `space.md`, top corners only rounded |
| Title | `text-heading`, `font-semibold`, `text-text-primary` |
| Body | `text-body`, `leading-body`, `text-text-primary` |
| Close control | `Button` `iconOnly`, 44px, `aria-label` |
| Motion | enter/exit at `duration.slow` with `easing.standard` / `easing.exit` |

**Binding rules — the full a11y contract is in force, none of it optional.**

- `role="dialog"`, `aria-modal="true"`, and an accessible name wired from the title.
- **Focus trap** — focus moves to the panel on open and cycles within it.
- **Escape dismisses.**
- **Focus restores to the trigger** on close.
- **Scroll lock** on the document behind the panel.
- Background content is `inert` while the overlay is open.
- The presentation variant flips at the **1024px band edge** only (D-23). No third overlay form may appear in a feature phase.
- Reduced motion: opacity-only at or below `duration.fast`, or static (`docs/governance/motion-rules.md` §3).

### 5.7 `Icon`

`lucide-react` at `strokeWidth={1.5}`, set once on a shared wrapper (D-21). Two sizes only: **24px** standalone and **16px** paired with a label. Ink is `textPrimary` in every state (§4.3); `currentColor` from the parent is the only permitted coloring mechanism. No icon is a status encoding by itself (§4.3), and no icon carries text.

## Shell Chrome

### 6.1 Layout structure

- `src/app/layout.tsx` is the **only root layout** and owns `<html>`, `<body>`, the Inter font variables, and the generated token stylesheet. It carries **no role chrome** (D-02).
- Three nested route-group layouts carry the role chrome: `(provider)`, `(patient)`, `(auth)`. `(auth)` is bare — a bare `canvas` field with a centred single column and no rail.
- All three nested inside one root layout, so a role switch between `/provider` and `/patient` does not trigger a full document reload.

### 6.2 `(provider)` — the persistent left icon rail

- Field: `Surface` `canvas` variant (`bg-canvas`, no shadow). Rail: `frame` fill.
- **Rail width is `space.lg` of rail padding plus a `space.2xl` content column** — every constituent is an on-scale step and the total is not written as a literal anywhere in this contract. This is a layout dimension, not a spacing value; it is stated here so the reviewer sees it instead of inferring it.
- Rail items are **`Button` `iconOnly` at `radius.pill`**, 44px in both axes at every band, stacked with `gap-sm`, ink `textPrimary` (never `frameForeground` — §6.3).
- **Active route:** `bg-surface-raised` + `shadow-raised` + `aria-current="page"`. The reference shows a fill highlight and no accent bar in the rail, and `INV-05` restraint wins — **the shell does not paint an accent marker in the rail**. Accent permission for an active-emphasis marker is recorded in §4, and deliberately left unused here.
- Items: home, patients, schedule, records, analytics — thin line icons, matching the reference's rail density with no text labels at this width.
- Below 768px the rail is replaced by the scrolling pill strip (§6.4).

### 6.3 `(provider)` — top bar

- `frame` fill, height two stacked `space.2xl` steps, `px-lg`, `gap-md`, `flex`.
- Left: `CompactControl` `search` (placeholder "Search patients", `font.size.body`).
- Right, in order: `Button` `primary` — the CTA, `bg-accent-soft`, `text-text-primary`, leading scan icon, label "Add new patient", `disabled` until Phase 004; then `Button` `iconOnly` notification bell with an `aria-label`; then the profile block — avatar, name at `font.size.body`, role at `font.size.label`, chevron.
- Provider **name and role text are `textPrimary`**, never `frameForeground` (see the reviewer item in §7).

### 6.4 `(provider)` — workspace top bar

Identical shell, with the tab group replacing the CTA position and the patient context replacing the profile block. The eight canonical tabs render as a `TabBar` (§5.3). Patient identity renders as `font.size.heading` `textPrimary` with a `font.size.label` secondary line.

### 6.5 `(patient)` — patient top bar and nav

Per `docs/governance/reference-ui-specification.md` §6 there is **no persistent sidebar** on patient surfaces. The top bar carries: a menu `Button` `iconOnly` (44px, `aria-label`), then right-aligned the label "Patient", an avatar with a state dot, and a bell. No CTA. Below 768px the same bar holds the scrolling pill strip where a tab set exists; the patient surfaces of Phase 2 have no primary tab set, so the menu control is the single navigation affordance and is not a hamburger-only collapse of a tab set.

### 6.6 Mobile navigation

- **≥1024px:** persistent rail + full top bar.
- **768–1023px:** rail persists; the body reflows toward 2 columns; top bar keeps the search field.
- **<768px:** rail removed; navigation becomes a horizontally scrolling **pill strip** (`gap-sm`, each item ≥44px tall, `radius.pill`) directly under the top bar. The provider strip carries one item ("Home"); the workspace strip carries the eight canonical tabs. Search collapses to a 44px `iconOnly` control that expands in place — it is never removed. Touch targets are ≥44px in both axes everywhere.

## Focus and Keyboard (FOUND-04)

**Focus-visible treatment — specified concretely, resolvable only through tokens.**

```
outline: 2px solid var(--color-text-primary);
outline-offset: 2px;
```

- **Ring color is `textPrimary`** — the only frozen token with usable contrast against every light fill (9.8:1 on `surface`, 10.5:1 on `surfaceRaised`, 11.4:1 on `accent`, 8.5:1 on `accentSoft`). `borderSubtle` and `textSecondary` are **not** used for the ring: at 1.9:1 and 1.3:1 they would fail a non-text indicator outright.
- **Radius is inherited** from the focused element, so a pill control shows a pill ring and an `xl` card shows an `xl` ring. No separate ring-radius token is introduced.
- **`outline-offset: 2px` on the `accentSoft` primary CTA only** — the gold fill and the dark ink are close enough that a 2px offset keeps the ring visually separate from the label. Everywhere else the offset is the default 0, hugging the element edge.
- **On the overlay panel**, which sits on a `textPrimary` scrim, the ring **inverts to `surface`** (9.8:1 against the scrim). This is the one place the ring is not `textPrimary`.
- `:focus-visible` only — never `:focus` — so a pointer user never sees a ring. `outline` is never set to `none` anywhere in the codebase; removing it is a `no-raw-hex`-class regression and fails FOUND-04.
- Every interactive primitive in §5 is keyboard reachable and shows this ring. Nothing is reachable by pointer only.

**Invariant readings, recorded so the reviewer does not have to adjudicate them fresh.**

| Reading | Decision |
|---------|----------|
| The 2px focus ring vs `INV-11` (rules and dividers are 1px) | `INV-11` governs rules, dividers and axis lines. A focus ring is a focus indicator, not a rule. The 2px ring and the 2px offset are control geometry and are **not** spacing or divider values. |
| Rail items use `radius.pill` although the reference shows a squircle highlight | `INV-08` names compact navigation controls explicitly and is the objective check. `radius.pill` wins over the reference's squircle here; the fill + `shadow.raised` active treatment still matches. |
| No `borderSubtle` on any control edge, including the search field | `INV-15` permits `borderSubtle` on dividers, table row lines, the timeline axis and the scrubber track only. The reference's search field has no edge; the fill carries it. |

**Focus order.** DOM order is the tab order; no positive `tabindex` anywhere. Rail → top bar → page content → overlay. On overlay open, focus moves to the panel and traps; on close it returns to the trigger. `docs/governance/reference-ui-specification.md` §4 requires every icon-only control to ship an accessible name, and Phase 002 implements that rather than guessing names.

### 10.1 Reduced-motion representation — the decision

**One section, last, and one Playwright project.** Two mechanisms, deliberately not two:

- **Section 10 renders every animated primitive twice** — once on the default branch, once on the reduced-motion branch — by driving the real `useReducedMotion` path (and, for anything GSAP-backed, the real `gsap.matchMedia` region), never a test-only flag. The section's caption states the contract in one line: opacity-only at or below `duration.fast`, or static for timeline choreography.
- **The `reduced-motion` Playwright project** captures the *entire* gallery and *every* shell at all four viewports under `reducedMotion: 'reduce'` (D-15), which is the machine evidence that the branch exists everywhere and not only in one section.

Splitting reduced motion across several sections would make the contract harder to read and would not add evidence — the project already captures the whole surface. The section exists because a human reviewer must be able to see the branch without running the harness.

### 10.2 Per-viewport behavior

The gallery is a dev surface but is still a surface: it obeys the same three bands as the product and introduces no mobile-only token, spacing value or radius (`docs/governance/responsive-rules.md` §5).

| Viewport | Band | Gallery behavior |
|----------|------|------------------|
| `1440x900` | desktop (≥1024px) | Canonical. Single column, `space-2xl` between sections, `space-xl` page padding. Overlay section shows the **modal** presentation. |
| `1280x800` | desktop (≥1024px) | Identical composition; the `space-2xl` column max-width means the content does not stretch. Overlay shows the **modal** presentation. |
| `768x1024` | tablet (768–1023px) | Sections become 2-up where a section holds specimen pairs, otherwise 1-up. Text buttons may drop to 32px tall; icon-only controls stay 44px. Overlay section shows the **sheet** presentation — the variant flips at the 1024px edge. |
| `390x844` | mobile (<768px) | One column. Every specimen row stacks vertically at `gap-md`; paired specimens become a single column. Buttons and compact controls are ≥44px in both axes. Tab strip scrolls horizontally. Page padding drops to `space.lg`. Overlay renders as a full-width **bottom sheet** with `space.md` insets. No horizontal page scroll at any section. |

Baseline coverage is the full matrix — 4 viewports × 2 motion states — for `dev-gallery` and every one of the five shell routes, at `tests/visual/baselines/{surface}/{viewport}/{state}.png` (D-14), captured against a production build with CSS animations disabled and tolerance `maxDiffPixelRatio: 0.01` / `threshold: 0.2` (`docs/governance/visual-qa-rules.md` §2). The baselines are machine-local: they were rasterized on the Windows workstation, and whoever later adds CI must regenerate them on that runner rather than assuming the committed PNGs transfer.

## Motion in the Shell

Tokenized, never locally declared (`docs/governance/motion-rules.md`): `duration.fast` for hover, toggle and pill state changes; `duration.slow` for the overlay panel enter and exit; `easing.standard` for entrances and emphasis, `easing.exit` for exits. No third duration, no fourth curve, no bounce, no overshoot. Framer Motion owns all Phase 2 motion; GSAP is installed for Phase 006 and reads `var(--duration-fast)` rather than a literal, and **is not used in Phase 002 code**.

**Reduced motion is a written invariant, not an aspiration.** Every animation routes through `useReducedMotion`; under `prefers-reduced-motion: reduce` it degrades to opacity-only at or below `duration.fast`, or renders statically. An animation without a reduced-motion branch fails this phase's acceptance.

## Contrast Findings and Reviewer Items

Computed by the method recorded in `docs/governance/reference-ui-specification.md` §3 (relative luminance ratios; the values live in `tokens.json` and are not restated here).

**Finding 1 — the resolution adopted in this contract.** Only `textPrimary` clears WCAG AA against every light fill in the frozen palette (9.8:1 on `surface`, 10.5:1 on `surfaceRaised`, 11.4:1 on `accent`, 8.5:1 on `accentSoft`). `textSecondary` measures 1.3:1 on `surface` and `frameForeground` 1.8:1 on `frame`; all four semantic status tints measure below 1.5:1 on `canvas` and `surface`. **Every label, value and icon in Phase 2 is therefore painted `textPrimary`, and the remaining color tokens are surface fills and decorative tints.** Status is carried by a `textPrimary` label plus a tint dot (§4.3), never by hue alone.

**Reviewer item A — does this contradict `reference-ui-specification.md` §2.1?** That table assigns `frameForeground` to "ink of frame icons and frame labels" and `textSecondary` to "secondary text and axis labels". At the frozen values neither can carry information. This spec overrides that assignment for Phase 002 shell chrome and confines `frameForeground` to frame decoration. The design gate must either **adjudicate this reading** or **re-open the frozen values**. Until then the shell follows this spec, because FOUND-04 is this phase's deliverable and a shell that renders unreadable chrome fails the phase regardless of what the prose says.

**Reviewer item B — status contrast is a product decision, not a styling one.** Because the status tints are decorative at these values, the tint is never the sole carrier of meaning. This is recorded rather than escalated: it is a strengthening of `INV-04`, not a contradiction of it.

**Reviewer item C — `frame`, `surface` and `surfaceMuted` are the same frozen value.** At
the values in `tokens.json` these three fills are byte-identical, and the measured ratios are
`frame`/`surface` **1.00:1**, `surface`/`surfaceMuted` **1.00:1**, `canvas`/`surface` **1.03:1**,
`surface`/`surfaceRaised` **1.09:1**. A `surfaceMuted` control therefore renders with **no
visible boundary** against a `surface` or `frame` parent, because the fill is the same and
`INV-15`/`INV-16` forbid the border that would create an edge while `INV-13` forbids a third
shadow. Affected in Phase 2: the compact search field (§5.4), inset note fields, the icon-toggle
off state and the `TabBar` container (§5.3). The search field is a primary interaction, and its
visual baseline would capture an invisible control.

**Owner decision, 2026-10-06 (CONTEXT.md D-27):** re-open `frame` and `surfaceMuted` and
**re-sample them from the binding references** using the Phase 001 method
(`docs/governance/reference-ui-specification.md` §3), so the four surface roles are visually
distinct; the 13 other tokens stay frozen and no new token may be added. The re-sampled values
carry the same owner visual review the original freeze required. **Until they are frozen, the
permitted fallback treatment for any control needing a visible edge is `surfaceRaised` +
`shadow.raised`** — this is the only sanctioned workaround, because a border fails INV-15/INV-16
and a third shadow fails INV-13.

**Reviewer item D — §0 authority statement.** Corrected in this revision: the no-restatement
claim is now scoped to color values, since spacing, type and icon sizes are shown numerically for
readability and match `tokens.json` exactly.

**Not a finding.** `accent` and `accentSoft` both clear AA against `textPrimary` ink, so the timeline nodes and the primary CTA are legible as specified.
