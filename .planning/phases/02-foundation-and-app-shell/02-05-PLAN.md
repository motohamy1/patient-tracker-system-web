# Plan 02-05 — `Surface`, `Icon` and `Button`: the primitive set's foundation

## Objective

Build the three primitives every other component composes from: the four-variant surface, the single stroke-width icon wrapper, and the four-variant button with its motion and touch-target contract.

Purpose: FOUND-02 asks that any screen can be composed from the shared primitive set rather than hand-rolled per-screen components. That is only true if the three lowest-level primitives are right and exhaustive — every later primitive and every shell surface inherits their token vocabulary, their focus behaviour and their elevation discipline.

Output: three primitives, a barrel, and three unit test files.

## Component signatures

- `Surface({ variant, size, as, className, children })` where `variant` is `'canvas' | 'surface' | 'surfaceMuted' | 'surfaceRaised'`, `size` is `'md' | 'lg' | 'xl'` and `as` is `'div' | 'section' | 'article'`.
- `makeIcon(LucideIcon)` returning a typed `TokenIcon`; `Icon` is the factory itself, re-exported for call sites. Sizes are `'sm' (16px)` and `'lg' (24px)` only.
- `Button({ variant, size, icon, disabled, type, ariaLabel, className, children })` where `variant` is `'primary' | 'secondary' | 'ghost' | 'iconOnly'`.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Generated token layer → component class names | Every visual decision in these components is a utility name resolved by Tailwind from the generated `@theme inline` block. A misspelled or non-existent utility renders as unstyled markup with no error. |
| `lucide-react` → `Icon` | Third-party SVG components are spread into our props; a spread that placed `strokeWidth` after our fixed value would silently defeat D-21. |
| Component → assistive technology | Rendered markup is consumed by screen readers; an unlabeled icon-only control is a shipped accessibility defect that no build step would catch. |
| User input → `Button` | The only user-driven path in these components is the pointer/keyboard activation of the control; nothing else is untrusted. |

## ASVS scope statement (recorded, not omitted)

**ASVS V2 Authentication, V3 Session Management, V4 Access Control, V5 Input Validation and V6 Cryptography were assessed and are NOT YET APPLICABLE to this plan.** These three components render no route, read no session, accept no user-supplied data beyond a click or a key press, and hold no credential. The access-control obligations belong to Phase 003 (D-03).

**ASVS V8 Data Protection** applies in the sense that no clinical value may be hardcoded into a primitive — a component is the wrong place for a patient identifier or a measurement, and FOUND-01's fixture rule would be violated by any such literal. **ASVS V12 Files and Resources** applies: `Icon` inlines third-party SVG as React components rather than loading an icon sprite or font from a CDN, so no third-party resource is fetched at runtime. **ASVS V14 Configuration** does not apply — no environment variable is read here.
