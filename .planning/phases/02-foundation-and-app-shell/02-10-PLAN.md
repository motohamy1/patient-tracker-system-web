# Plan 02-10 — The dev-only primitives gallery, behind the D-26 gate

## Objective

Build the review and baseline surface: a ten-section gallery that renders every primitive, both overlay presentations, the focus ring on every interactive element, and the reduced-motion branch — reachable only under the harness's environment flag and absent from every real deployment.

Purpose: D-14 requires baselines for the gallery, and `docs/governance/visual-qa-rules.md` §2 requires capture against a production build. A literal `NODE_ENV` gate makes those two requirements mutually exclusive, which is why D-26 amends D-16. The gallery is also the only place a human reviewer can see FOUND-04's focus ring and FOUND-05's reduced branch without running the harness.

Output: the gate module, the route, the gallery and its sections, and the gate's unit test.

## The ten sections, in order (binding, from `02-UI-SPEC.md` §10)

1. Surfaces — the four variants on a `canvas` field, each labelled with its fill, radius, padding, and explicitly whether it takes `shadow.raised` or none.
2. Typography — the four sizes by the two weights, the eyebrow style, and a `tabular-nums` specimen beside a proportional one.
3. Icons — both sizes at stroke width 1.5, ink `textPrimary`, the six shell icons at 24px, and one 16px icon paired with a label showing the icon-to-label gap.
4. Buttons — all four variants in rest, hover, active, focus-visible and disabled states; the `primary` specimen carrying a printed note that it is `accentSoft`, not `accent`.
5. Pills and tabs — the three status pills each with its tint dot and `textPrimary` label, a "tint removed" row, the tab group, and the eight canonical tab labels spelled out.
6. Compact controls — search field, icon toggle off and on, range toggle inactive and active.
7. Empty state — one specimen per slot combination so all three slots are baseline-capturable.
8. Overlay — the modal presentation at and above 1024px and, below that edge, the sheet presentation of the same primitive, both with the `textPrimary` scrim and the focus ring on the first focusable element.
9. Focus and keyboard — every interactive primitive from sections 4 through 8 with the focus treatment applied, one row per primitive.
10. Reduced motion — every animated primitive rendered twice, once per branch, driving the real hook.

## ASVS scope statement (recorded, not omitted)

**ASVS V2 Authentication, V3 Session Management, V4 Access Control, V5 Input Validation and V6 Cryptography were assessed and are NOT YET APPLICABLE to this plan.** The gallery renders no identity, holds no session, accepts no user input and stores no secret. It is a static review surface whose gate is a configuration concern, not an access-control mechanism — the gallery is not protected by an authorization check, it is *absent* from real deployments, which is a stronger and simpler property.

**ASVS V8 Data Protection applies to this plan**, because this is the one file that imports the fixture module. The mitigations are: the fixtures carry shape and no value; the gate keeps the route out of real deployments; and plan 02-11 adds a build-output assertion that the fixture module never reaches the client bundle. **ASVS V12 Files and Resources** applies minimally — the gallery creates no upload path and no executable content. **ASVS V14 Configuration is the category this plan is built around**, and the control is that the gate's truth table is unit-tested and the variable is confined to one file that plan 02-11 owns.
