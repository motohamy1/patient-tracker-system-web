# Plan 02-09 — The `(auth)` and `(patient)` groups, the root 404, and the dev fixtures

## Objective

Complete the locked route map: the bare `(auth)` group with `/login`, the `(patient)` group with `/patient` and `/patient/home`, the root `not-found.tsx` that `/` resolves to, and the typed dev fixtures that stay behind the dev gate.

Purpose: FOUND-01 requires the whole URL map to render as empty-but-real shells, and D-01 locks it so later phases fill bodies rather than invent paths. D-18 requires dev fixtures to exist as typed stubs with no clinical values, and requires them to be structurally unreachable from a product route — that constraint is what keeps PHI-shaped data out of the shipped bundle.

Output: one shell component, five route files, one fixture module and one scope-enforcing test.

## Trust Boundaries

| Boundary | Description |
|---|---|
| `src/lib/dev/**` → everything else | The fixture module holds PHI-*shaped* structures. Its containment inside one directory is the boundary; an import from a product route would put that structure into the shipped bundle. |

## ASVS scope statement (recorded, not omitted)

**ASVS V2 Authentication and V3 Session Management were assessed and are NOT YET APPLICABLE to this plan, with one deliberate exception recorded explicitly:** `/login` exists as a route but renders **no** form, no credential input and no session creation, and the page says so in its own copy. That is the D-03 discipline — a form that looks real is a fake gate, which is worse than none. Authentication and session management are Phase 003.

**ASVS V4 Access Control** is NOT YET APPLICABLE and carries the same hard negative rule as plan 02-08: no client-side gate, no role read from client-held state, no `middleware.ts`. Both new role layouts carry the Phase 003 **server-side** role-resolution marker.

**ASVS V5 Input Validation** is assessed: this plan's routes take no route parameter and accept no form input, so there is nothing to validate. The `[patientId]` discipline belongs to plan 02-08 and is not repeated here.

**ASVS V6 Cryptography** is assessed in its negative form: no secret, key, hash or credential appears in any file this plan writes, and `/login` stores nothing.

**ASVS V8 Data Protection applies to this plan and is the reason the fixture scope test exists**: a `Patient`-shaped structure in the shipped bundle is the PHI-leakage pattern the research names. The mitigation is structural containment plus two failing tests, not a review convention. **ASVS V12 Files and Resources** does not apply — no upload, no user path, no executable content. **ASVS V14 Configuration** does not apply here — no environment variable is read; the dev-route gate arrives in plan 02-10.
