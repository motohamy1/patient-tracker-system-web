# Plan 02-03 — Token codegen, the generated dual-emission CSS layer, the base stylesheet and the single root layout

## Objective

Build the token pipeline the entire product rests on: one script that reads `docs/governance/tokens.json` and writes both the Tailwind v4 `@theme inline` block and the `:root` block, plus the shared base stylesheet and the one root layout that owns `<html>`, the font and the tokens.

Purpose: this is the mechanism that makes "no raw hex outside the token layer" structurally true rather than a review convention. Every primitive in plans 02-05 through 02-07 and every shell surface in plan 02-08 draws its color, radius, spacing, type, shadow and motion values from the artifacts this plan produces.

Output: `scripts/token-namespaces.mjs`, `scripts/generate-tokens.mjs`, the two generated (gitignored) artifacts, `src/app/globals.css`, `src/app/layout.tsx`, `vitest.config.ts`, and the generator's unit test.

## The namespace map (binding, from `02-RESEARCH.md` Pattern 2)

`color.*` → `--color-*`; `radius.*` → `--radius-*`; `space.*` → `--spacing-*`; `font.size.*` → `--text-*`; `font.weight.*` → `--font-weight-*`; `font.lineHeight.*` → `--leading-*`; `shadow.*` → `--shadow-*`; `motion.easing.*` → `--ease-*`. `motion.duration.*` → `--duration-*`, which has **no** Tailwind namespace and therefore appears only in the `:root` block and in the generated TypeScript module.

## Trust Boundaries

| Boundary | Description |
|---|---|
| `docs/governance/tokens.json` → `scripts/*.mjs` | A committed JSON file is read and its values are transformed into CSS and TypeScript that every later artifact consumes. A malformed or hand-edited value propagates silently. |
| `scripts/generate-tokens.mjs` → `src/styles/tokens.generated.css` | A generated artifact on disk is imported by the browser stylesheet; it is the boundary where a build-tool output becomes a shipped document. |
| `next/font/google` → build | A build-time network fetch of font binaries from Google Fonts. Nothing is fetched at runtime, but the build does reach a third party. |
| Build process → `.next/` client bundle | Everything reachable from `src/app/layout.tsx` is emitted into a bundle that ships to a browser in a PHI product. |

## ASVS scope statement (recorded, not omitted)

**ASVS V2 Authentication, V3 Session Management, V4 Access Control, V5 Input Validation and V6 Cryptography were assessed and are NOT YET APPLICABLE to this plan.** This plan writes two Node scripts, one stylesheet, one root layout and one test config. It creates no route handler, no session, no cookie, no credential and no user input path. Those obligations are owned by Phase 003.

**ASVS V8 Data Protection** applies in one concrete form: a raw token value must not reach the **client bundle** by any route other than the generated CSS layer. A component importing `docs/governance/tokens.json` directly would place values in the JavaScript bundle where the `no-raw-hex` check (plan 02-04) cannot see them, so the prohibition is a real control, not a style preference. **ASVS V10 Malicious Code** applies to the `next/font/google` build-time fetch and is satisfied by the Phase 001 registry audit and the exact-version pin from plan 02-02. **ASVS V12 Files and Resources** applies: the only static assets this plan introduces are the self-hosted font files `next/font` emits into `.next/static/media`. **ASVS V14 Configuration** does not yet apply — no environment variable is read here; `ALLOW_DEV_ROUTES` arrives in plans 02-09 and 02-10.
