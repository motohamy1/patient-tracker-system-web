# Plan 01-01 — Pixel sampling, frozen `tokens.json`, and the reference manifest

## Objective

Produce the canonical machine-readable token layer `docs/governance/tokens.json` and the machine-readable reference registry `docs/governance/reference-manifest.json`. The token values are **produced by this plan's execution**, not written by this plan: the plan supplies the sampling method, the tool command shapes, the windows-per-token floor, the re-sample agreement check, and the machine assertions. No hex value appears anywhere in this plan text, and none may appear outside `tokens.json`.

## Non-goals (fence)

This plan writes exactly two files. It does not create `tokens.css` (Phase 002 generates it from this JSON, D-07), does not create any lint or CI rule (Phase 002, D-17), does not create the Playwright harness (Phase 002, D-18), and does not write any prose governance document (those belong to plans 01-03 through 01-06).

## Locked structural decisions this plan enforces

1. **Raw-hex home.** `docs/governance/tokens.json` is the single home of every raw hex literal under `docs/governance/`. The per-window provenance evidence therefore lives in a `provenance` key **inside `tokens.json`**, and the human-facing `reference-ui-specification.md` provenance section (plan 01-04) reproduces only window *coordinates* and cites `tokens.json` for the per-window RGB. This is the separation between the normative token values and the non-normative evidence record that keeps the `no-raw-hex` invariant checkable.
2. **`provenance` and `review` are marked non-normative.** Each carries the literal marker `"normative": false` and a `"disclaimer"` string stating that Phase 002 code generation reads only `color`, `radius`, `space`, `font`, `shadow` and `motion`.
3. **Shadow ink derivation.** The `rgba(...)` ink of both `shadow.raised` and `shadow.overlay` is the decimal RGB of the sampled `textPrimary` hex, never an arbitrary black. Alphas stay `0.07`, `0.05`, `0.16`, `0.10` and the geometry strings stay `0 2px 6px`, `0 8px 24px`, `0 12px 32px`, `0 4px 12px` (UI-SPEC §6, D-03).
4. **Exactly two shadows.** `shadow` has exactly the keys `raised` and `overlay` (D-03).
