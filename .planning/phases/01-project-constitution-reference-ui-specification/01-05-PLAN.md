# Plan 01-05 — `ui-invariants.md` and `visual-qa-rules.md`

## Objective

Write the two greppable enforcement documents of the governance package: `docs/governance/ui-invariants.md` (what must not drift, as named `INV-xx` IDs, covering GOV-03) and `docs/governance/visual-qa-rules.md` (how a phase is judged visually, as the 12-row §21 gate plus the Playwright harness contract, covering GOV-05).

## The INV-xx registry (fixed; these IDs are the contract)

| ID | Grouping | Invariant |
|---|---|---|
| INV-01 | Visual character (§2.1) | Token-only styling — every color resolves through a semantic token; no raw hex, no default Tailwind color utility |
| INV-02 | Visual character (§2.1) | No dark frame or dark navigation — D-01 light warm-gray with olive undertone |
| INV-03 | Visual character (§2.1) | No generic blue/indigo/purple healthcare substitution |
| INV-04 | Visual character (§2.1) | One accent family — status color is `success`/`info`/`warning` only, never a new tint family |
| INV-05 | Visual character (§2.1) | Accent restraint — accent appears only on the reserved list and at most 10% of visible area |
| INV-06 | Visual character (§2.1) | No gamification — no points, levels, streaks, fireworks, celebration or gamified animation |
| INV-07 | Geometry (§2.3) | Radius scale — only the five steps `radius.sm`, `radius.md`, `radius.lg`, `radius.xl`, `radius.pill` |
| INV-08 | Geometry (§2.3) | Pill controls — compact navigation and controls use `radius.pill` |
| INV-09 | Geometry (§2.3) | No sharp corners — no control has a corner radius at or below 4px |
| INV-10 | Geometry (§2.3) | Spacing scale — every gap and padding is a `space.` step; no page-level section gap above 32px |
| INV-11 | Geometry (§2.3) | Hairline lines — rules and dividers are 1px; no thick rules |
| INV-12 | Geometry (§2.3) | Compactness — no bulky tile and no card holding one line of content or less |
| INV-13 | Depth (§2.4) | Exactly two elevation levels — `shadow.raised` and `shadow.overlay`, no third |
| INV-14 | Depth (§2.4) | No invented shadows — components use the two tokens, never a local shadow value |
| INV-15 | Depth (§2.4) | Hairline-only borders — `borderSubtle` only on true dividers, table row lines, the timeline axis and the scrubber track |
| INV-16 | Depth (§2.4) | No outlined cards — card edges separate by shadow, not by border |
| INV-17 | Depth (§2.4) | No excessive glass or neumorphism; scrims derive from `textPrimary`, never a new token |
